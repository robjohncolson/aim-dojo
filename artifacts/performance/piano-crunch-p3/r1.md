# R1: supplied-native musical context

Implemented locally on the earlier-bloom HEAD, `23ca7cd`. This parcel fixes the measured ordinary-context source-retention path. It is not a claim of a doorway frame-rate improvement.

`pianoContextAlign` supplies a separate native AudioContext to Tone through public APIs before the first owned instrument is constructed. It copies the previous sample rate, latency hint, musical lookAhead (0.1 s), update interval (0.05 s), worker clock and BPM. An application-local facade resolves Transport, Draw, Destination/Master, Listener and context through public getters. This is necessary because the pinned library's exported singleton constants retain their original context after `setContext`. The library exports and minified dependency are untouched. The unused original context is disposed once; an independent latch prevents context replacement on an audio-init retry. The accepted listener/sphere context remains separate, with two sphere instruments and its existing immediate scheduling.

`CFG.pianoNativeContext:0` restores the original context/exports path. Legacy `?piano=0` also retains it. No instrument patch, release, note, groove gate, voice cap, musical call argument, grading, wall, renderer or earlier-bloom setting changes. Runtime delta: 55 lines before generated mirrors (44 additions, 11 removals, including replacement of the obsolete singleton comment).
